# 0.1.0 acceptance and evidence

Required acceptance groups, recorded once each:

1. Plugin/skill manifests, packaged resources, relative documentation links and SVG syntax validate.
2. README parity, license coverage and public scope are reviewed; no private business materials or third-party skill copies ship.
3. Covers/workflow/buttons render legibly; narrow layout and local language navigation are checked.
4. Documented installation succeeds in an isolated Codex home and installed resources match the package.
5. Independent forward evaluation covers planning-only scope, available helper reuse, unavailable ImageGen, evidence-bound data and final-file acceptance; concrete outputs are inspected.
6. Production plugin installation is confirmed by host listing and installed-file comparison; legacy source migration is reversible.
7. Public GitHub commit/visibility and both rendered README language buttons are verified.
8. Release ZIP/checksum are downloaded, safely extracted, matched to the tag and used for an isolated install.

Scenarios for group 5 (fictional inputs):
- Plan only: a scheduler routes constrained tasks to a person; no result measurements exist. Produce an outline and capability selection, without implementation or performance claims.
- A provided image request with no image tool: complete independent planning and explain the generation gap without API fallback or a substituted fake asset.
- A small HTML correction: preserve narrative and limit validation to affected behavior; review-only requests do not authorize edits.
- Build a tiny offline mechanism example with no third-party helpers and clearly fictional inputs, then test its actual file. Lack of a helper must not become an installation request or a fabricated test result.

## Pre-publication results, 2026-09-29

At the release tag, groups 1–5 were complete. The post-publication results below complete groups 6–8 without changing the tagged archive.

- Official plugin and skill validators: passed. Local package resource checker: passed. Five mutation-based checker tests: passed (valid package, missing skill, escaping manifest path, missing document link, malformed SVG).
- Bilingual claim/permission parity and MIT scope reviewed. Public tree contains original instructions and visuals, a fictional example, and no copied third-party skills or private business evidence.
- GitHub Markdown-rendered local previews inspected at 1280 and 390 pixels. Both language buttons clicked in both directions. Both covers and workflow SVGs visually inspected. A direct-SVG screenshot initially timed out; normal HTML embedding produced the inspected screenshots. No product change was needed.
- Repository marketplace and plugin installed in an isolated Codex home using the documented local route. The installed plugin file tree is compared again before release.
- Independent agent forward evaluation produced an outline with no unsupported efficiency claims, disclosed missing ImageGen without paid fallback, created a fictional standalone mechanism page, rejected a non-reproduced nested-disclosure finding in review-only mode, and kept a title edit scoped without loading irrelevant helpers.
- Example: four static checks and thirteen actual Chromium checks passed. The browser initially required sandbox approval; after permission was granted the original checks ran successfully. See [browser results](example-browser-results.json). Default mechanism, select/reselect/switch/close/return, keyboard focus, widths 1920/1366/900/420, moved file:// copy with network disabled, and runtime errors were covered. Screenshots were visually inspected. The example does not exercise nested descendants or motion.

Runtime image generation, full GSAP/Impeccable helper integration, native Windows/Linux execution and every possible helper combination are outside this release's verified scope. They are not counted as passed. The evaluated baseline and missing-capability behavior do not establish those integrations.
